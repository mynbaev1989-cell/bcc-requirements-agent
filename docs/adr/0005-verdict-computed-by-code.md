# ADR-0005. Вердикт и оценку считает код, а не модель

Статус: принято · Дата: 27.11.2026

## Контекст
Главный результат отчёта: можно ли начинать разработку и тест-дизайн. Если вердикт пишет модель, то при том же наборе находок он может отличаться от прогона к прогону, а ответ «Да» трудно объяснить. При неполной проверке модель склонна давать мягкий вердикт.

## Решение
Функция `_finalize` в `reqcheck/pipeline.py` считает всё по списку находок, без запросов к LLM.
- Оценка требования: 100 минус штрафы по серьёзности (`SEVERITY_PENALTY` в `reqcheck/agents.py`: critical 35, major 20, minor 8) и минус 5 за нарушенный критерий без находки. Светофор: зелёный от 80, жёлтый от 50, ниже красный.
- Оценка документа: среднее по требованиям минус штраф за находки уровня набора (8, 4, 1).
- Вердикт для разработки: есть критичные, значит «Нет»; есть существенные, значит «Условно»; иначе «Да». Вердикт для тестирования смотрит на противоречия и непроверяемые требования.
- Если смысловая проверка неполная (нет LLM, Reviewer не оценил требования, упал шаг, ищущий дефекты), «Да» не выдаётся, максимум «Условно» с пометкой.
- Приоритеты (до 7 находок) и оценка ценности тоже считаются кодом.
Модель влияет на вердикт только через набор находок, который уже прошёл сверку цитат и Critic.

## Последствия
- Плюсы: один набор находок даёт один вердикт; правила читаются и тестируются; нет «Да» при неполной проверке.
- Минусы: веса штрафов (35/20/8) выбраны нами, а не выведены из данных, и не откалиброваны на реальных проектах банка. Вердикт грубый, три градации. Ошибочная находка, прошедшая сверку и Critic, всё равно меняет вердикт.

## Альтернативы
- Вердикт от LLM с обоснованием: отвергли, нестабилен и не проверяется.
- Только счётчики без вердикта: отвергли, нужен ответ на вопрос «можно ли начинать разработку и тестирование».
