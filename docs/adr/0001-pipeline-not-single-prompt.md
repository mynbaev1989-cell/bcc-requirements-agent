# ADR-0001. Конвейер из ролей вместо одного большого промпта

Статус: принято · Дата: 27.11.2026

## Контекст
Нужно проверить документ требований по критериям ТЗ: неполнота, противоречия, непроверяемость, пропуски. Один промпт «найди все проблемы» даёт ответ в свободной форме, который нельзя перепроверить по частям. Если модель недоступна или ответила мусором, отчёта нет совсем. Лимиты бесплатного тарифа тоже бьют по одному огромному запросу.

## Решение
Прогон разбит на роли, по одному агенту на шаг (`reqcheck/steps.py`, `build_plan()`): 14 стадий, в них 16 шагов, три шага (Reviewer и два Analyst) идут параллельно. Часть шагов код (чтение, нарезка, правила, сверка цитат, калибровка критичности, нумерация), часть LLM (Extractor, Reviewer, Consistency и Gap, Critic, Clarifier, Resolver). Оркестратор (`reqcheck/orchestrator.py`) выполняет `Step.run`, а `Step.apply` вызывает строго в порядке плана, поэтому отчёт детерминирован. Если LLM нет или шаг упал с `LLMError`, пишется диагностика и вызывается `Step.fallback`. Запасной вариант на коде есть у Extractor (эвристика по структуре), Clarifier (вопросы из находок) и Resolver; у остальных LLM-шагов он пустой: шаг пропускается, сбой попадает в диагностику, и вердикт тогда не «Да».

## Последствия
- Плюсы: отчёт выходит и без модели (правила находят 38 из 104 дефектов, `eval/README.md`); каждую роль можно отключить и измерить (полный конвейер 100 из 104, без GapFinder 98 из 104); запросы короче.
- Минусы: больше запросов к LLM (документ на 40–45 требований тратит 12–14 запросов из 20 в сутки на бесплатном тарифе); больше кода и промптов, которые надо держать согласованными.
- Вклад Consistency и Gap лежит внутри доверительного интервала на 7 документах: это направление, а не доказанный эффект.

## Альтернативы
- Один промпт со всем документом: отвергли, нет перепроверки находок, нет отката при сбое, один отказ роняет весь прогон.
- Агентный фреймворк с самостоятельным планированием: отвергли, порядок шагов известен заранее, а детерминизм отчёта важнее гибкости.
