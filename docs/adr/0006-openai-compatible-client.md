# ADR-0006. OpenAI-совместимый клиент для моделей внутри контура

Статус: принято · Дата: 27.11.2026

## Контекст
Документ требований банка может быть конфиденциальным и не должен уходить в облако Google. Изначально агент работал только с Gemini через ключ.

## Решение
`OpenAICompatClient` (`reqcheck/llm_openai.py`) даёт тот же интерфейс, что `GeminiClient` (`generate_json`, `stats`, `model`), и работает с любым сервером с API `/chat/completions` (Ollama, vLLM, LM Studio). Он включается, если задана переменная `REQCHECK_LLM_BASE_URL`; модель берётся из `--model` или `REQCHECK_LLM_MODEL`, ключ `REQCHECK_LLM_API_KEY` необязателен и в отчёт не попадает. Выбор делает `ConnectLLMStep` (`reqcheck/steps.py`): документ уходит только на этот адрес. В паспорт попадают схема и хост без пути и учётных данных. Клиент написан на `urllib`, без новых зависимостей, температура 0, JSON-режим (если сервер отвечает 400, один раз повторяет без него). При отказе соединения (сервер не запущен, адрес не найден) клиент помечает сервер недоступным на весь прогон и не делает повторов: на Windows каждая попытка к закрытому порту занимает около 4 с. Шаги за секунды переходят на запасные варианты (ADR-0001), причина идёт в диагностику.

## Последствия
- Плюсы: данные банка не покидают контур; нет привязки к одному провайдеру; без лишних пакетов; ключ Gemini не нужен.
- Минусы: качество на локальных моделях мы не замеряли, замеры сделаны на `gemini-3.5-flash-lite`. Слабая модель может хуже отдавать JSON; повторы и запасные варианты это смягчают, но полноту поиска не вернут. Кэш отдельный: в ключ входит `base_url`.
- Правила, сверка цитат и вердикт от модели не зависят и работают так же.

## Альтернативы
- Только Gemini: отвергли, нельзя для данных, которые нельзя отправлять наружу.
- SDK `openai` или LiteLLM: отвергли, лишняя зависимость ради одного эндпоинта.
- Отдельный клиент под каждый локальный сервер: отвергли, все они понимают OpenAI-совместимый API.
