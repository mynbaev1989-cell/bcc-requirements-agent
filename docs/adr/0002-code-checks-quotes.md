# ADR-0002. Код сверяет цитаты с документом, модели не верим на слово

Статус: принято · Дата: 27.11.2026

## Контекст
Каждая находка LLM обязана ссылаться на цитату из документа. Модели иногда выдумывают цитату или слегка перефразируют её. Отчёт с «цитатой», которой нет в документе, подрывает доверие к остальным находкам.

## Решение
Класс `Grounder` (`reqcheck/grounding.py`) ищет каждую цитату в тексте документа: сначала точное совпадение после нормализации (регистр, кавычки, тире, `ё`, разметка Markdown), затем по частям, если в цитате есть «…» (части должны лежать рядом, не дальше 400 символов), затем нечётко через `difflib` с порогом 0,86 на окне до трёх строк. Если цитата встречается несколько раз, берётся вхождение, ближайшее к строке требования. Находка получает `verified`, если найдена хотя бы одна цитата (`reqcheck/agents.py`). Шаг `GroundStep` (`reqcheck/steps.py`) выбрасывает находки LLM без подтверждённой цитаты и оставляет в находке только найденные цитаты; число отброшенных идёт в паспорт (`dropped_ungrounded`). Находки правил кода подтверждены по построению. Номер строки в отчёте определяет код, а не модель.

## Последствия
- Плюсы: выдуманных цитат в отчёте нет, ссылки на строки точны. На 7 документах сверка отсеяла 9 находок; без неё точность падает с 86% до 82%, а ложных critical становится 3 вместо 1 (`eval/README.md`, относительно варианта без критика).
- Минусы: порог 0,86 подобран эмпирически, верная находка с сильно переписанной цитатой будет потеряна. Находка с одной верной и одной выдуманной цитатой проходит: выдуманная просто убирается.
- Сверка проверяет, что цитата есть в тексте, но не что вывод из неё верен. Это задача Critic (ADR-0004).

## Альтернативы
- Верить ответу модели: отвергли, разница по точности и ложным critical измерена выше.
- Требовать от модели только номера строк: отвергли, модели ошибаются в номерах чаще, чем в тексте цитаты (наблюдение, отдельно не замеряли).
- Только точное совпадение: отвергли, модель часто меняет пробелы, кавычки и тире.
