- Тогда: Накопленные расходы за месяц уменьшаются до 45 000 ₸

**Повторное превышение порога в рамках одного календарного месяца** — к R-006 (Ф-3)

- Дано: Карта cardId='demo-42' с порогом 50 000 ₸. В текущем месяце расходы достигли 50 000 ₸ и 1 push уже был отправлен. Далее был проведен возврат на 5 000 ₸ (расходы стали 45 000 ₸)
- Когда: Проводится новая покупка на 6 000 ₸ (расходы становятся 51 000 ₸)
- Тогда: Повторный push не отправляется, так как на карту приходится максимум один push за календарный месяц

**Изменение порога на меньший при накопленных расходах выше нового порога** — к R-007 (Ф-4)

- Дано: Карта cardId='demo-42', накопленные расходы 40 000 ₸, текущий порог 50 000 ₸ (push не отправлялся)
- Когда: Клиент изменяет порог на 30 000 ₸
- Тогда: Накопленная сумма 40 000 ₸ сохраняется; отправляется ли push сразу или при следующей покупке — поведение не определено документом — требуется уточнение (см. вопрос автору)

**Идемпотентность повторного события процессинга о покупке** — к R-012

- Дано: Карта cardId='demo-42', накопленные расходы 48 500 ₸, порог 50 000 ₸. Проведена покупка 1 500 ₸, итог стал 50 000 ₸, отправлен 1 push
- Когда: Поступает повторное дублирующее событие процессинга по той же операции 1 500 ₸
- Тогда: Итоговая сумма расходов остается 50 000 ₸, повторный push не отправляется

**Попытка изменения порога для чужой карты** — к R-023

- Дано: Авторизованный клиент с сессией Bearer TOKEN, не являющийся владельцем карты 'alien-99'
- Когда: Выполняется GET-запрос /alerts/saveLimit c cardId='alien-99', amount=50000, enabled=1
- Тогда: Сервер возвращает статус HTTP 404 с телом {"message":"Карта не найдена"}

**Изменение данных (POST/PUT вместо GET) через метод сохранения** — к R-017

- Дано: Документ определяет тип метода сохранения REST API как GET c URL /alerts/saveLimit
- Когда: Отправляется POST-запрос на /alerts/saveLimit c параметрами cardId='demo-42', amount=50000, enabled=1
- Тогда: Поведение не определено документом — требуется уточнение (см. вопрос автору)
