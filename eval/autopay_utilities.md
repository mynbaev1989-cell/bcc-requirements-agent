# ТЗ: Автоплатёж за коммунальные услуги

## 1. Общие сведения

| Параметр | Значение |
|---|---|
| Система | Мобильный банк, модуль «Платежи» |
| Владелец требований | Продуктовая команда платежей |
| Статус | Черновик |
| Согласующие | Руководитель продукта, архитектор, служба информационной безопасности |
| Целевая аудитория | Физические лица, держатели дебетовых карт банка |

## 2. Цели

- Снизить долю просроченных платежей за коммунальные услуги среди клиентов банка.
- Сделать оплату коммунальных услуг удобной для клиента без ежемесячных ручных действий.
- Сократить число обращений в контакт-центр по вопросам оплаты ЖКХ.

## 3. Функциональные требования

- ФТ-1. Клиент может создать правило автоплатежа, указав поставщика услуг, лицевой счёт, карту списания и максимальную сумму платежа в тенге.
- ФТ-2. Система проверяет лицевой счёт у поставщика, сохраняет правило и отправляет клиенту SMS с подтверждением создания.
- ФТ-3. Система запрашивает задолженность у поставщика каждый день в 09:00 по времени Астаны.
- ФТ-4. Если сумма задолженности не превышает максимальную сумму платежа, система списывает её с карты в течение 24 часов после обнаружения.
- ФТ-5. Если задолженность превышает максимальную сумму платежа, платёж не выполняется, а клиенту отправляется push-уведомление с суммой долга.
- ФТ-6. Система должна быстро обрабатывать списания по правилам автоплатежа.
- ФТ-7. Клиент может приостановить или удалить правило автоплатежа в любой момент.
- ФТ-8. Один клиент может иметь не более 5 активных правил автоплатежа.
- ФТ-9. Один клиент может создать до 10 активных правил автоплатежа.
- ФТ-10. При недостатке средств на карте система по возможности повторяет попытку списания.
- ФТ-11. Для хранения правил использовать СУБД PostgreSQL 15 с партиционированием таблицы по коду поставщика.
- ФТ-12. Если поставщик не отвечает, система повторяет запрос.
- ФТ-13. Комиссия за автоплатёж составляет 1% от суммы платежа, но не более 500 тенге.

## 4. Нефункциональные требования

- НФТ-1. Время обработки одного списания не должно превышать 3 секунд с момента получения задолженности.
- НФТ-2. Система должна быть удобной в использовании.
- НФТ-3. Доступность сервиса автоплатежей составляет не менее 99,9% в календарный месяц.
- НФТ-4. Журнал всех списаний хранится 5 лет с момента операции.
- НФТ-5. Все запросы к поставщикам передаются по TLS версии не ниже 1.2.

## 5. Требования к данным

| Поле | Тип | Обязательность | Описание |
|---|---|---|---|
| rule_id | UUID | да | Идентификатор правила |
| provider_code | строка, до 16 символов | да | Код поставщика из справочника |
| account_number | строка, до 20 символов | да | Лицевой счёт клиента у поставщика |
| card_id | UUID | да | Карта списания |
| max_amount | целое число | да | Максимальная сумма платежа |
| status | перечисление | да | ACTIVE, PAUSED, DELETED |

## 7. Интеграция и API

| Метод | Путь | Описание |
|---|---|---|
| POST | /api/v1/autopay/rules | Создание правила автоплатежа |
| GET | /api/v1/autopay/rules/{rule_id} | Получение правила |
| GET | /api/v1/autopay/rules/{rule_id}/pause | Приостанавливает правило автоплатежа |
| DELETE | /api/v1/autopay/rules/{rule_id} | Удаление правила |

Параметры запроса на создание правила:

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| provider_code | string | да | Код поставщика |
| account_number | string | да | Лицевой счёт |
| card_id | string | да | Идентификатор карты |
| max_amount | integer | да | Максимальная сумма платежа в тиынах |

Коды ответов на создание правила:

| Код | Описание |
|---|---|
| 201 Created | Правило создано, возвращается rule_id |
| 201 Created | Ошибка валидации: лицевой счёт не найден у поставщика |
| 401 Unauthorized | Клиент не аутентифицирован |
| 409 Conflict | Правило с такими параметрами уже существует |

## 8. Критерии приёмки

| Исходные условия | Действие | Ожидаемый результат |
|---|---|---|
| Задолженность 20 000 тенге, максимальная сумма платежа 30 000 тенге | Наступило время запроса задолженности | Списано 20 000 тенге, комиссия составляет 300 тенге |
| Задолженность обнаружена в 09:00, средств на карте достаточно | Система выполняет списание | Платёж проведён не позднее чем через 48 часов после обнаружения |
| Задолженность 50 000 тенге, максимальная сумма платежа 30 000 тенге | Наступило время запроса задолженности | Платёж не выполнен, клиент получил push-уведомление |
| У клиента есть активное правило | Клиент нажимает «Приостановить» | Статус правила PAUSED, запросы задолженности прекращены |
