# ТЗ: P2P-перевод по номеру телефона

## 1. Общие сведения

| Параметр | Значение |
|---|---|
| Система | Мобильный банк, модуль «Переводы» |
| Владелец требований | Продуктовая команда переводов |
| Статус | На согласовании |
| Согласующие | Руководитель продукта, служба рисков, комплаенс |
| Целевая аудитория | Физические лица, клиенты банка с активной картой |

## 2. Цели

- Позволить клиенту отправить деньги другому клиенту банка, зная только его номер телефона.
- Уменьшить долю переводов, выполняемых через кассу и банкоматы.
- Снизить число ошибок при вводе реквизитов получателя.

## 3. Функциональные требования

- ФТ-1. Клиент выбирает получателя из списка контактов телефона или вводит номер вручную в международном формате.
- ФТ-2. Система показывает клиенту имя получателя в маскированном виде (имя и первая буква фамилии) до подтверждения перевода.
- ФТ-3. Система находит получателя по номеру телефона среди клиентов банка.
- ФТ-4. Максимальная сумма одного перевода составляет 500 000 тенге.
- ФТ-5. Переводы до 150 000 тенге в календарный месяц комиссией не облагаются, с суммы сверх этого порога взимается комиссия 1%.
- ФТ-6. Подтверждение перевода выполняется одноразовым кодом из SMS, код действителен 5 минут.
- ФТ-7. Система списывает сумму с карты отправителя, зачисляет её получателю, отправляет чек обеим сторонам и сохраняет операцию в истории.
- ФТ-8. Перевод должен выполняться оперативно.
- ФТ-9. Максимальная сумма разового перевода равна 1 000 000 тенге.
- ФТ-10. Система запрашивает дополнительное подтверждение при необходимости.
- ФТ-11. Клиент может отменить перевод до момента ввода одноразового кода.
- ФТ-12. Получатель видит входящий перевод в истории операций и получает push-уведомление в течение 10 секунд после зачисления.

## 4. Нефункциональные требования

- НФТ-1. Время выполнения перевода от подтверждения до зачисления не превышает 5 секунд при нагрузке до 200 переводов в секунду.
- НФТ-2. Интерфейс перевода должен быть интуитивно понятным.
- НФТ-3. Сопоставление номера телефона со счётом выполнять через Redis-кэш с временем жизни записи 5 минут.
- НФТ-4. Система должна обеспечивать высокую надёжность.
- НФТ-5. Данные о переводах шифруются при хранении алгоритмом AES-256.

## 5. Требования к данным

| Поле | Тип | Обязательность | Описание |
|---|---|---|---|
| transfer_id | UUID | да | Идентификатор перевода |
| sender_card_id | UUID | да | Карта отправителя |
| recipient_phone | строка, формат E.164 | да | Номер телефона получателя |
| amount | целое число | да | Сумма перевода |
| fee | целое число | да | Комиссия по переводу |
| created_at | дата и время UTC | да | Момент создания перевода |

## 7. Интеграция и API

| Метод | Путь | Описание |
|---|---|---|
| GET | /api/v2/p2p/recipient | Поиск получателя по номеру телефона |
| GET | /api/v2/p2p/send | Выполняет перевод и списывает средства с карты |
| POST | /api/v2/p2p/confirm | Подтверждение перевода одноразовым кодом |
| POST | /api/v2/p2p/cancel | Отмена перевода до подтверждения |

Параметры запроса на перевод:

| Параметр | Тип | Обязательный | Описание |
|---|---|---|---|
| recipient_phone | string | да | Номер получателя в формате E.164 |
| sender_card_id | string | да | Карта отправителя |
| amount | integer | да | Сумма перевода в тысячах тенге |
| comment | string | нет | Комментарий до 100 символов |

Коды ответов на подтверждение перевода:

| Код | Описание |
|---|---|
| 200 OK | Перевод проведён, возвращается transfer_id |
| 400 Bad Request | Неверный или просроченный одноразовый код |
| 404 Not Found | Недостаточно средств на карте отправителя |
| 429 Too Many Requests | Превышено число попыток ввода кода |

## 8. Критерии приёмки

| Исходные условия | Действие | Ожидаемый результат |
|---|---|---|
| В текущем месяце переводов не было, баланс карты 300 000 тенге | Клиент переводит 200 000 тенге и подтверждает кодом | Списано 200 000 тенге плюс комиссия 1 000 тенге |
| Одноразовый код отправлен 4 минуты назад | Клиент вводит верный код | Код отклонён как просроченный |
| Номер получателя зарегистрирован в банке | Клиент вводит номер и нажимает «Далее» | Отображается маскированное имя получателя |
| Клиент ввёл неверный код 3 раза подряд | Клиент вводит код в четвёртый раз | Возвращается ответ 429, повторная попытка доступна через 15 минут |
| Перевод проведён | Получатель открывает историю операций | Входящий перевод отображается в списке |
