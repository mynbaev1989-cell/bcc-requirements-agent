# Техническое задание: Зарплатный проект для юридических лиц

**Версия:** 1.2 от 14.03.2026
**Статус:** согласовано с продуктовым комитетом

## 1. Цель

Обеспечить юридическим лицам загрузку реестра выплат и массовое зачисление заработной платы на карточные счета сотрудников.

## 2. Область

В область входят загрузка реестра, проверка, зачисление и формирование отчёта. Выпуск карт и расчёт налогов не входят.

## 3. Роли

- Бухгалтер клиента — формирует и загружает реестр выплат.
- Руководитель клиента — подтверждает реестр к исполнению.
- Менеджер банка — сопровождает клиента и видит статусы реестров.

## 5. Интеграция

Метод загрузки реестра: `POST /api/v1/payroll/registries`. Формат тела запроса: JSON, кодировка UTF-8.

| Параметр | Тип | Обязательность | Описание |
|----------|-----|----------------|----------|
| company_bin | string(12) | да | БИН организации-плательщика |
| registry_id | | да | Идентификатор реестра в системе клиента |
| pay_date | string | да | Дата выплаты в формате, принятом в банке |
| comment | string | | Комментарий к платежу, отображаемый сотруднику |
| items | array | да | Строки реестра, не более 10 000 записей в одном запросе |
| currency | string(3) | да | Код валюты по ISO 4217, например KZT |

Успешный ответ содержит HTTP-код 202 и идентификатор принятого реестра.

В случае ошибки метод возвращает ответ с описанием проблемы.

## 7. Статусы реестра

| Статус | Описание |
|--------|----------|
| Загружен | Файл принят, проверка не начата |
| Проверен | Проверка завершена, ожидается подтверждение |
| Исполнен | Выплаты переданы на зачисление |
| Отклонён | Реестр не принят к исполнению |

## 8. Глоссарий

- **Реестр выплат** — файл со списком сотрудников и сумм к зачислению.
- **ИИН** — индивидуальный идентификационный номер физического лица.
- **БИН** — бизнес-идентификационный номер юридического лица.
- **Операционный день** — день, в котором банк проводит платежи клиентов.

## 9. Допущения и ограничения

- Сотрудники клиента уже имеют карточные счета в банке на момент загрузки реестра.
- Клиент самостоятельно отвечает за корректность сумм и реквизитов в загружаемом файле.
- Расчёт налогов и удержаний выполняется в учётной системе клиента до загрузки реестра.
- Загрузка реестра через мобильное приложение банка в данной версии не поддерживается.
- Ручная корректировка принятого реестра сотрудником банка не допускается.
