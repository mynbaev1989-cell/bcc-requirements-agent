# ТЗ: Рассрочка 0-0-12 при оплате в магазине-партнёре через мобильное приложение

## 1. Общие сведения

| Параметр | Значение |
|---|---|
| Продукт | Рассрочка 0-0-12 |
| Канал | Мобильное приложение банка (iOS, Android) |
| Срок рассрочки | 12 месяцев |
| Переплата клиента | 0 тенге |
| Сумма покупки | от 15 000 до 1 500 000 тенге |
| Комиссия магазина-партнёра | 6% от суммы покупки |
| Валюта | KZT |
| Владелец документа | Продуктовая команда POS-кредитования |

## 2. Цели

- Дать клиенту возможность оформить рассрочку на покупку за 2 минуты, не выходя из магазина.
- Увеличить долю безналичных покупок у партнёров на 15% за первый год после запуска.
- Снизить долю отказов на этапе оформления до уровня не выше 20% заявок.

## 3. Функциональные требования

- ФТ-1. Клиент выбирает рассрочку 0-0-12 на экране оплаты после сканирования QR-кода магазина-партнёра.
- ФТ-2. Система рассчитывает ежемесячный платёж как сумму покупки, делённую на 12.
- ФТ-3. Максимальная сумма покупки в рассрочку составляет 1 000 000 тенге.
- ФТ-4. Система проверяет кредитный лимит клиента и при необходимости запрашивает дополнительные документы.
- ФТ-5. Система запрашивает кредитный отчёт клиента в кредитном бюро, рассчитывает скоринговый балл и отправляет клиенту push-уведомление о решении.
- ФТ-6. Запрос в кредитное бюро выполняется автоматически при выборе рассрочки, отдельное согласие клиента не запрашивается.
- ФТ-7. Решение по заявке выдаётся клиенту не позднее чем через 30 секунд после отправки заявки.
- ФТ-8. Клиент подтверждает рассрочку вводом одноразового кода из SMS, срок действия кода составляет 5 минут, допускается не более 3 попыток ввода.
- ФТ-9. За просрочку начисляется пеня 0,5% в день от суммы платежа, предельный размер пени составляет 10% годовых от суммы покупки.
- ФТ-10. При возврате товара магазин-партнёр инициирует отмену рассрочки.
- ФТ-11. Клиент может погасить рассрочку досрочно, полностью или частично, в любой момент без комиссии и штрафов.
- ФТ-12. Ежемесячный платёж списывается со счёта клиента в конце дня 25 числа каждого месяца.
- ФТ-13. Данные заявок хранятся в базе данных PostgreSQL 14 в таблице installment_orders.

## 4. Нефункциональные требования

- НФТ-1. Система должна работать быстро при пиковой нагрузке.
- НФТ-2. Доступность сервиса оформления рассрочки составляет не менее 99,9% в календарный месяц, измеряется системой мониторинга.
- НФТ-3. Время ответа API расчёта графика платежей не превышает 2 секунд (95-й перцентиль) при нагрузке 500 запросов в секунду.
- НФТ-4. Номер карты клиента записывается в журнал событий целиком для упрощения разбора инцидентов.
- НФТ-5. Мобильное приложение поддерживает iOS 15 и выше, Android 9 и выше.

## 5. Данные

| Поле | Тип | Описание |
|---|---|---|
| order_id | string | Идентификатор заявки |
| partner_id | string | Идентификатор магазина-партнёра |
| amount | integer | Сумма покупки в тенге |
| term_months | integer | Срок рассрочки в месяцах |
| monthly_payment | integer | Ежемесячный платёж |
| status | string | Статус заявки: NEW, APPROVED, CONFIRMED, REJECTED, CANCELLED, CLOSED |
| created_at | datetime | Дата и время создания заявки |

## 6. Интеграция и REST API

Базовый путь API: /api/v1. Формат обмена: JSON, кодировка UTF-8.

| Метод | Путь | Назначение |
|---|---|---|
| POST | /installments/quote | Расчёт графика платежей |
| POST | /installments | Создание заявки на рассрочку |
| GET | /installments/{id}/confirm | Подтверждение заявки кодом из SMS |
| GET | /installments/{id} | Получение статуса заявки |
| POST | /installments/{id}/cancel | Отмена заявки до подтверждения |

Пример запроса на создание заявки:

```json
{"partner_id": "P-1042", "amount": 250000, "installment_months": 12, "client_id": "C-77"}
```

Коды ответов:

| Код | Описание |
|---|---|
| 200 | Запрос выполнен успешно |
| 400 | Некорректные параметры запроса |
| 404 | Заявка не найдена |
| 409 | Заявка уже подтверждена |
| 429 | Превышен лимит запросов |

## 7. Отчётность

ТБД, содержание раздела не определено.

## 8. Критерии приёмки

- АК-1. Решение по заявке выдаётся клиенту в течение 60 секунд после отправки заявки.
- АК-2. При покупке на 120 000 тенге ежемесячный платёж равен 10 000 тенге, переплата равна 0 тенге.
- АК-3. После трёх неверных вводов SMS-кода заявка переходит в статус REJECTED, повторный ввод невозможен.
- АК-4. Вызов POST /installments/{id}/cancel для подтверждённой заявки возвращает код 409.
